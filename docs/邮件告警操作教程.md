## 1. 功能简介

系统在以下三种情况发生时,会自动向你在后台设置的**一个或多个邮箱**发送告警邮件:

| 告警类型 | 说明 |
|---|---|
| 备份失败 | 定时备份执行失败(如 pg_dump 报错、连不上数据库、认证失败、磁盘不可写等) |
| 同步失败 | 定时同步任务整任务失败(如获取 token 失败、远程 API 拉取失败、目标库连接失败),或**全部记录导入失败**(一条都没成功) |
| 进程崩溃 | 服务进程遇到未捕获异常即将退出时(由 pm2 自动重启) |

核心特点:

- **多收件人**:支持同时发送给多个邮箱(运维、开发各一份)。
- **三类独立开关**:每种告警可单独开启/关闭。
- **防轰炸**:同类告警在设定的时间间隔内不会重复发送,间隔可自由配置。
- **测试邮件**:一键发送测试邮件,验证配置是否正确。

## 2. 快速开始(五步走)

如果不想看长篇说明,按下面 5 步即可完成:

```
① 服务器更新代码并重启  →  ② 准备一个邮箱并拿到"授权码"
→  ③ 打开「系统配置 → 邮件告警」填写 SMTP 信息和收件人
→  ④ 点「保存配置」 →  ⑤ 点「发送测试邮件」,收件箱收到即配置完成
```

每一步的详细操作见下文对应章节。

---

## 3. 第一步:更新服务器部署

邮件告警依赖新包 `nodemailer`(纯 JavaScript,无需编译环境),按以下步骤更新服务器:

```bash
# 1. 进入部署目录(按你的实际路径)
cd /www/wwwroot/0.db_sync

# 2. 拉取最新代码
git pull

# 3. 安装后端依赖(会自动下载 nodemailer)
cd server && npm install

# 4. 重启服务(pm2 进程名按你的实际名称,通常为 data-sync)
pm2 restart data-sync
```

**验证更新是否成功**:浏览器打开系统 → 顶部菜单「系统配置」→ 如果能看到「邮件告警」标签页(在"PostgreSQL 数据源"旁边),说明更新成功。

> 提示:如果 `npm install` 很慢,可以使用国内镜像:`npm install --registry=https://registry.npmmirror.com`

## 4. 第二步:准备发件邮箱(获取 SMTP 授权码)

告警邮件通过一个**发件邮箱**发出。你需要准备一个邮箱,并获取它的 **SMTP 地址**和**授权码**。

### 4.1 常见邮箱速查表

| 邮箱类型 | SMTP 服务器 | 推荐端口/加密 | 密码填什么 |
|---|---|---|---|
| QQ 邮箱 | smtp.qq.com | 465 / SSL | **授权码**(非 QQ 密码) |
| 网易 163 邮箱 | smtp.163.com | 465 / SSL | **授权码**(非登录密码) |
| 腾讯企业邮箱 | smtp.exmail.qq.com | 465 / SSL | 登录密码或客户端专用密码 |
| 阿里企业邮箱 | smtp.qiye.aliyun.com | 465 / SSL | 登录密码 |
| 其他自建/企业邮箱 | 询问邮箱管理员 | 一般 465 / SSL | 询问管理员 |

> **建议用 465 端口(SSL 加密)**。25 端口(不加密)很多云服务商默认封禁,容易发送失败。

### 4.2 QQ 邮箱获取授权码(最常用,以 QQ 邮箱为例)

1. 浏览器登录 [mail.qq.com](https://mail.qq.com);
2. 点击顶部 **设置** → **账号**(部分新版本入口为:设置 → 账户);
3. 找到「POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务」区块;
4. 找到 **IMAP/SMTP 服务**,点击 **开启**;
5. 按页面提示用 QQ 手机版发送一条验证短信;
6. 发送成功后,页面会显示一个 **16 位授权码**——**立即复制保存**,这个码只显示一次;
7. 之后配置界面里:「SMTP 账号」填你的 QQ 邮箱地址,「SMTP 密码/授权码」填这 16 位授权码。

### 4.3 网易 163 邮箱获取授权码

1. 登录 [mail.163.com](https://mail.163.com);
2. 顶部 **设置** → **POP3/SMTP/IMAP**;
3. 开启 **IMAP/SMTP 服务**,按提示短信验证;
4. 页面会弹出授权码(只显示一次),复制保存备用。

> 注意:个人邮箱(QQ/163 等)**必须用授权码**,直接填邮箱登录密码会报 `535 Authentication failed` 错误。

## 5. 第三步:界面配置逐项详解

打开 **系统配置 → 邮件告警**,界面自上而下依次是:

### 5.1 SMTP 服务器信息

| 界面字段 | 怎么填 | 示例 |
|---|---|---|
| **SMTP 服务器** | 发件邮箱的 SMTP 地址(见 4.1 速查表) | `smtp.qq.com` |
| **加密方式** | 一般选「SSL/TLS (465)」。切换加密方式时,端口若还是默认值(465/587/25)会**自动跟着切换** | SSL/TLS (465) |
| **端口** | 一般不用手动改,跟随加密方式即可 | `465` |
| **发件人地址** | 可以留空(默认用 SMTP 账号作为发件人)。想让显示的发件人更好看时才填 | `data-sync-alert@example.com` |
| **SMTP 账号(邮箱)** | 发件邮箱的完整地址 | `yourname@qq.com` |
| **SMTP 密码 / 授权码** | 个人邮箱填授权码,企业邮箱一般填登录密码(见界面下方的灰色提示文字) | 16 位授权码 |

### 5.2 收件人

- 在「收件人邮箱(可添加多个)」输入框中**输入邮箱地址后按回车**,即添加一个收件人;
- **支持一次粘贴多个**:粘贴以逗号、分号或空格分隔的多个邮箱(如 `a@x.com,b@y.com`),会自动拆分成多个;
- 点每个收件人标签上的 × 可删除;
- 可以配置任意多个收件人,告警时**所有收件人都会收到**。

### 5.3 通知开关(三个)

| 开关 | 控制内容 | 建议 |
|---|---|---|
| **备份失败通知** | 定时备份失败时发邮件 | 开 |
| **同步失败通知** | 定时同步任务失败/全部记录失败时发邮件 | 开 |
| **进程崩溃通知** | 服务进程异常退出前发邮件 | 开 |

### 5.4 告警间隔(防轰炸)

| 字段 | 含义 | 默认值 | 范围 |
|---|---|---|---|
| **失败告警间隔(分钟)** | 同一个任务/备份配置失败后,在这个时间内再次失败**不会重复发邮件** | 30 分钟 | 1–1440 |
| **崩溃告警间隔(分钟)** | 进程崩溃发过一封邮件后,在这个时间内即使再次崩溃也不发(防止 pm2 反复重启导致邮件风暴) | 10 分钟 | 1–1440 |

> 举例:同步任务 A 在 09:00 失败并发了告警,09:20 又失败(间隔 30 分钟)→ 不发;10:00 再失败 → 超过 30 分钟,再次发送。任务 A 和任务 B 的节流互不影响。

## 6. 第四步:保存并发送测试邮件

1. 填写完上述内容后,点击 **「保存配置」**,提示"邮件告警配置已保存";
2. 点击 **「发送测试邮件」**;
3. 到收件箱查收,主题为 **【数据同步】测试邮件**。若收件箱没有,检查垃圾邮件文件夹;
4. 多个收件人时,**每个收件人都会收到**测试邮件。

**重要**:

- 「发送测试邮件」使用的是**已保存**的配置。所以务必**先保存、再测试**;修改了配置也要先重新保存再测试;
- 测试邮件不受开关和告警间隔的限制,任何时候都可以发;
- 测试失败时,界面会显示具体错误信息(常见错误见 [FAQ](#10-常见问题排查faq))。

## 7. 告警触发规则详解(什么时候会收到邮件)

这一章解释清楚哪些情况会告警、哪些不会,避免误以为"没收到邮件=功能坏了"。

### 7.1 会收到告警的情况

| 场景 | 告警类型 | 邮件标题示例 |
|---|---|---|
| 定时备份执行失败(pg_dump 出错、连不上库等) | 备份失败 | 【数据同步告警】备份「竞赛系统备份」失败 |
| 定时同步任务中某个配置整任务失败(token 失效、API 拉不到、目标库连不上) | 同步失败 | 【数据同步告警】同步任务「竞赛系统同步」执行失败 |
| 定时同步任务全部记录导入失败(失败数 > 0 且成功数为 0) | 同步失败 | 【数据同步告警】同步任务「xxx」全部记录导入失败 |
| 服务进程遇到未捕获异常、即将退出重启 | 进程崩溃 | 【数据同步告警】服务进程崩溃 |

### 7.2 不会收到告警的情况(设计如此)

| 场景 | 为什么不告警 | 去哪里看结果 |
|---|---|---|
| **手动**点击「立即备份」后失败 | 你本人就在界面上操作,能直接看到结果 | 备份配置页的备份日志 |
| **手动**点击「立即执行」任务后失败 | 同上 | 任务管理页的执行日志 |
| 同步任务**部分**记录失败(有成功也有失败,如 1000 成功 / 3 失败) | 个别记录插入失败属于正常业务波动,不算任务失败 | 执行日志的失败计数 + 失败记录 CSV 文件 |
| 手动停止备份 | 是人工操作 | — |
| 处在告警间隔期内重复失败 | 防轰炸,详见第 9 章 | 服务日志(pm2 logs) |

> 简单记:**只有"定时任务没人盯着的时候"失败才发邮件;手动操作失败当面看结果。**

## 8. 告警邮件长什么样

所有告警邮件均为 HTML 格式,红色标题 + 信息表格,便于手机快速阅读。

**备份失败邮件**包含:备份配置名、数据库名、备份格式、错误信息、服务器时间。

**同步失败邮件**包含:任务名称、同步配置名、目标表、错误信息(或失败记录数)、服务器时间。

**崩溃邮件**包含:错误信息(含堆栈,超长截断到 2000 字符)、服务器时间,并注明"进程即将退出,pm2 会自动重启"。

每封邮件底部都有一行说明:*"同类告警在 N 分钟内不会重复发送"*,N 就是你配置的告警间隔。

## 9. 防轰炸机制(告警间隔)说明

**为什么需要它**:如果数据库密码改了,定时备份每分钟失败一次,没有节流的话你一早上会收到几百封邮件——这就是"邮件轰炸",反而淹没了真正重要的信息。

**工作机制**:

- **失败告警间隔**(默认 30 分钟):按"任务/备份配置"分别计算。比如任务 A 发过一次告警后,A 在间隔期内再失败不发;但任务 B、备份配置 C 的失败**不受影响**,照常发送。
- **崩溃告警间隔**(默认 10 分钟):进程崩溃的时间戳**保存在数据库里**,即使服务被 pm2 反复重启,间隔期内也只发一封崩溃邮件,防止"重启风暴 → 邮件风暴"。
- 修改间隔后**立即生效**(保存配置即可,无需重启服务)。

**推荐配置**:

| 场景 | 失败告警间隔 | 崩溃告警间隔 |
|---|---|---|
| 任务执行频率高(每几分钟一次) | 30–60 分钟 | 10–30 分钟 |
| 任务每天只跑一两次 | 5–15 分钟(基本不会触发节流) | 10 分钟 |
| 希望每类失败都尽可能收到(接受较多邮件) | 1–5 分钟 | 1–5 分钟 |

## 10. 常见问题排查(FAQ)

### 测试邮件发送失败

**报错 `535 Authentication failed`(或 Login fail)**

- 原因:SMTP 密码填错。**个人邮箱(QQ/163)必须填授权码,不是邮箱登录密码**;
- 解决:回到第 4 章重新获取授权码;注意授权码中间不能有多余空格。

**报错 `getaddrinfo ENOTFOUND xxx`**

- 原因:SMTP 服务器地址写错(比如把 `smtp.qq.com` 写成 `qq.com`),或服务器 DNS 异常;
- 解决:核对 4.1 速查表中的 SMTP 地址。

**报错 `connect ETIMEDOUT` 或连接超时**

- 原因:服务器到 SMTP 端口的网络不通。最常见的是**云服务商封禁了 25 端口**,或者安全组限制了出方向流量;
- 解决:加密方式改用 **SSL(465 端口)** 再试;仍不通则检查云服务器安全组的出方向规则,放行 465 端口。

**报错 `邮件告警未配置或 SMTP 信息不完整`**

- 原因:还没保存配置就点了测试,或必填项(服务器/账号/密码)没填;
- 解决:先点「保存配置」再点「发送测试邮件」。

**报错 `未设置收件人邮箱`**

- 原因:收件人列表为空;
- 解决:在收件人输入框输入邮箱后按回车,再保存并测试。

### 测试邮件成功,但真实告警收不到

按顺序检查:

1. **对应的开关打开了吗?**——比如只开了"备份失败通知",同步失败自然不会有邮件;
2. **失败的是不是手动触发的?**——手动执行不告警(见 7.2);
3. **是不是还在告警间隔期内?**——上一次告警发出后的间隔分钟内的重复失败不再发(看邮件底部的那行说明,或调小间隔测试);
4. **垃圾邮件文件夹查了吗?**——告警邮件很可能被归入垃圾箱;
5. **收件人地址配对了吗?**——到「邮件告警」页检查收件人列表内容。

### 邮件总是进垃圾箱

让收件人把发件邮箱(即 SMTP 账号)**添加到通讯录 / 白名单**,或在邮箱设置中将该地址标记为"不是垃圾邮件"。

### 崩溃后只收到一封邮件,后面重启很多次都没收到

这是**崩溃告警间隔**在起作用(防重启风暴),属于正常保护行为。如果希望更灵敏,把「崩溃告警间隔」调小(最小 1 分钟);崩溃详情始终可以在 `pm2 logs` 中查看。

### 同步有几十条失败记录,为什么没收到邮件?

**部分记录失败不算任务失败**。只要有一条成功,任务就视为正常完成,失败明细在:任务管理 → 执行日志(失败计数、失败记录 CSV 下载)。只有"一条都没成功"的全部失败才触发告警——这是有意设计,避免因为个别脏数据天天收邮件。

## 11. 注意事项与已知限制

1. **进程被强制杀掉时无法告警**:如果进程是被操作系统直接杀死(内存溢出 OOM killer、服务器断电、`kill -9`),进程自己来不及发邮件。这类情况建议配合:
   - pm2 内存保护:`pm2 start xxx --max-memory-restart 300M`(内存超限自动重启);
   - 服务器层面的监控告警(如云厂商的宕机告警)。
   应用内部的未捕获异常(如之前 sql.js WASM 内存损坏那类)可以正常收到崩溃邮件。

2. **SMTP 密码明文存储**:与系统内 PG 数据源密码、Token Secret 的存储方式一致,保存在服务器本地的 SQLite 数据库中。请确保服务器登录权限可控。

3. **告警只覆盖定时调度**:手动操作的结果以界面显示为准,不发邮件。

4. **错误信息截断**:邮件中的错误信息最长 2000 字符,超长部分会截断;完整错误始终记录在执行日志/备份日志和服务日志(pm2 logs)里。

## 12. 配置的导出与迁移

邮件告警配置已纳入系统的配置导出/导入功能(分类名:**notify**):

- **导出**:系统配置 → 配置导入/导出 → 勾选「邮件告警」→ 导出,得到 JSON 文件;
- **导入**:在另一套环境上导入该 JSON,即可把 SMTP、收件人、开关、间隔整套配置带过去,无需重新填写。

> ⚠️ 导出文件中**包含 SMTP 密码/授权码明文**,请像保管密码一样保管导出文件,不要发送到不安全的渠道。
